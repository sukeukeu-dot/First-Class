# 신전떡볶이 웹사이트 리뉴얼 — Design System

> 이 문서는 `sinjeon` 프로젝트의 완성된 메인 페이지 구현을 분석해, 이후 제작할 서브 페이지의 브랜드 정체성과 UI 규칙을 통일하기 위한 기준이다.
>
> **분석 기준 파일**
> - `sinjeon/index.html`
> - `sinjeon/CSS/main.css`
> - `../css/default.css` (공통 리셋)
> - `../css/pretendardvariable.css` (폰트 선언)
>
> **작성 원칙:** 아래의 수치와 색상은 저장소 코드에서 확인한 값만 기록했다. 메인 페이지에 없는 디자인 요소는 기존 규칙인 것처럼 단정하지 않고, 필요한 경우 '서브 페이지 적용 제안'으로 구분한다. 외부 브랜드 사이트로 연결하는 링크는 이 문서에 추가하지 않는다.

---

## 1. Project Overview

### 사이트 목적

현재 메인 페이지는 신전떡볶이 브랜드의 주요 정보와 콘텐츠를 한 페이지에서 소개하는 웹사이트 리뉴얼 결과물이다.

HTML 구조에서 확인되는 주요 콘텐츠는 다음과 같다.

1. 브랜드 영상(Hero)
2. 메뉴 소개
3. 브랜드 스토리
4. 공지사항·이벤트·SNS 소식
5. 인스타그램 게시물 영역
6. 회사 정보와 푸터

GNB에는 메뉴, 매장 찾기, 브랜드, 신전 APP, 소식, 고객센터가 배치되어 있어, 향후 서브 페이지에서 이 정보 구조를 확장할 수 있다.

### 디자인 방향

현재 구현은 **브랜드 핑크를 중심으로 밝고 친근한 분위기를 전달하고, 음식 및 브랜드 이미지를 크게 보여주는 이미지 중심 구성**이 특징이다.

- 화이트와 아주 옅은 오프화이트를 기본 배경으로 사용한다.
- 핑크를 제목, 메뉴 탭의 선택 상태, CTA, 푸터 등에 반복 사용한다.
- 그린은 GNB의 상호작용 상태와 메가 메뉴 구분선에 사용한다.
- 레드는 일부 텍스트 강조와 CTA hover에 사용한다.
- 큰 제목, 넓은 이미지, 넉넉한 섹션 여백으로 콘텐츠를 구분한다.
- 모바일에서는 다단 레이아웃을 단순화하고 일부 콘텐츠를 가로 스크롤로 제공한다.

## 2. Brand Identity

### 코드에서 확인되는 시각적 정체성

| 요소 | 현재 구현의 특징 |
|---|---|
| 대표 색상 | 핑크 `#F6878B` |
| 보조 강조색 | 그린 `#008657`, 레드 `#D23023` |
| 기본 바탕 | 화이트 `#FFFFFF`, 오프화이트 `#FFFDFC` |
| 글꼴 | Pretendard Variable |
| 이미지 | 메뉴 사진, 브랜드 이미지, 뉴스 썸네일, SNS 이미지 |
| 형태 | 캡슐형 CTA, 작은 라운드의 이미지 카드 |
| 분위기 | 밝은 배경과 핑크 포인트를 활용한 친근하고 경쾌한 인상 |

### 브랜드 자산 사용 규칙

- 헤더와 푸터의 로고는 기존 프로젝트의 이미지 자산을 우선 재사용한다.
- 브랜드를 나타내는 이미지와 아이콘은 임의로 다른 스타일로 교체하지 않는다.
- 메뉴·뉴스·SNS 이미지의 분위기가 서로 지나치게 달라지지 않도록 이미지 톤을 맞춘다.
- 새로운 서브 페이지에서도 핑크를 핵심 강조색으로 유지하되, 모든 요소를 핑크로 처리하지 않는다.

## 3. Design Principles

### 3.1 컬러의 역할을 구분한다

핑크는 브랜드를 기억하게 하는 주요 색상이며, 그린과 레드는 기능과 상태를 구분하는 보조 색상이다. 새 색상을 추가하기보다 기존 CSS 변수를 먼저 재사용한다.

### 3.2 이미지와 제목으로 콘텐츠 주제를 빠르게 전달한다

메인 페이지는 메뉴 사진과 뉴스 썸네일을 넓게 노출한다. 서브 페이지에서도 해당 콘텐츠가 무엇인지 이미지와 명확한 제목으로 빠르게 이해할 수 있도록 구성한다.

### 3.3 콘텐츠 위계를 분명하게 만든다

섹션 영문 라벨, 큰 섹션 제목, 설명 문장, CTA 순서로 정보를 전달한다. 서브 페이지에서도 제목과 설명, 보조 정보의 크기와 굵기를 구분한다.

### 3.4 반복 UI는 같은 규칙을 사용한다

헤더, GNB, CTA, 카드, 푸터 등 여러 페이지에서 반복될 요소는 같은 클래스 또는 공통 스타일을 사용한다. 페이지마다 유사한 컴포넌트를 새로 만들면서 서로 다른 규칙을 적용하지 않는다.

### 3.5 반응형에서도 정보와 행동을 유지한다

화면이 작아질 때 단순히 모든 요소를 축소하지 않는다. 열 수를 줄이거나 콘텐츠를 세로로 쌓고, 메인 페이지처럼 일부 카드 영역은 가로 스크롤을 활용한다.

### 컬러 적용 규칙

- 새 페이지의 기본 배경은 흰색 또는 `--color-background-page`를 사용한다.
- 브랜드를 강조하는 제목과 주요 CTA에는 `--color-brand-pink`를 우선 사용한다.
- 네비게이션의 상호작용 상태는 현재 구현처럼 그린을 사용한다.
- 레드는 주요 단어 강조 또는 CTA hover처럼 제한된 상황에서 사용한다.
- 표에 없는 새로운 브랜드 컬러를 임의로 만들지 않는다. 콘텐츠상 별도 색이 꼭 필요하다면 기존 디자인과의 조화를 먼저 검토한다.

## 5. Typography

### 폰트

- 기본 글꼴: `"Pretendard Variable", Pretendard, sans-serif`
- 폰트 선언 파일: `../css/pretendardvariable.css`
- 실제 폰트 파일 경로: `../fo/PretendardVariable.woff2`
- 기본 본문 굵기: `400`

### 타이포그래피 적용 규칙

- 페이지의 대표 제목은 섹션 제목과 본문보다 크게 설정해 정보 위계를 만든다.
- 본문과 설명은 읽기 쉬운 크기와 행간을 유지한다. 메인 페이지의 설명 문장은 1.8, 카드 제목은 1.5의 행간을 사용한다.
- 영문 섹션 라벨은 13px, 굵기 600, 자간 0.12em으로 본문 제목보다 작은 보조 정보로 사용한다.
- 모바일에서는 제목과 탭 크기를 단계적으로 줄인다. 데스크톱의 큰 제목을 그대로 유지해 화면을 압박하지 않는다.
- CSS에서 별도 행간이 지정되지 않은 요소에 대해 임의의 기존 규칙을 주장하지 않는다. 새 서브 페이지에서 필요한 경우 가독성에 맞게 정하되 메인 페이지의 위계와 어울리도록 한다.

## 6. Layout & Spacing

### 공통 너비

| 항목 | 실제 규칙 |
|---|---|
| 최대 콘텐츠 너비 | `--content-max-width: 1720px` |
| 섹션 컨테이너 | `.section-container { width: 100%; max-width: var(--content-max-width); margin-inline: auto; }` |
| 푸터 내부 | `max-width: var(--content-max-width)` |
| 헤더 내부 콘텐츠 | PC `width: calc(100% - 80px)`, 최대 너비 1720px |
| 메가 메뉴 내부 | PC `width: calc(100% - 80px)`, 최대 너비 1720px |

### 섹션 여백

| 화면 기준 | `.inner-section` 패딩 |
|---|---|
| 기본 | `110px 20px 70px` |
| 1100px 이하 | `80px 24px 56px` |
| 700px 이하 | `62px 16px 48px` |

### 레이아웃 방식

- **Header:** Flex를 사용해 로고와 GNB를 양쪽으로 배치한다. GNB는 오른쪽에 정렬한다.
- **메가 메뉴:** PC에서는 CSS Grid 6열로 GNB별 하위 링크를 나눈다.
- **메뉴 목록:** PC에서는 Grid 4열로 카드가 배치된다. 모바일에서는 카드 폭을 넓게 두어 가로 스크롤로 탐색한다.
- **브랜드 스토리:** PC에서는 이미지와 텍스트를 2열 Grid로 배치하고, 모바일에서는 1열로 쌓는다.
- **뉴스:** PC에서는 4열, 1100px 이하에서는 2열, 모바일에서는 1열로 바뀐다.
- **인스타그램:** PC에서는 3열 Grid와 가로 스크롤을 사용하고, 모바일에서는 카드 폭을 화면보다 넓게 두어 가로로 탐색한다.
- **푸터:** PC에서는 Flex 가로 배치, 모바일에서는 세로 배치로 전환한다.

### 간격과 정렬 원칙

- 여러 카드가 한 줄에 반복될 때 같은 Grid gap을 사용해 간격을 일정하게 유지한다.
- 이미지와 텍스트를 함께 사용하는 영역은 수직·수평 정렬을 명확히 한다.
- 섹션별 배경을 화이트와 오프화이트로 교차해 콘텐츠 영역을 구분한다.
- 새 페이지의 콘텐츠 폭은 `--content-max-width`를 우선 사용한다. 별도의 임의 최대 너비를 만들지 않는다.

## 7. Component

### 7.1 Header / GNB

**HTML 구조:** `.site-header > .header-inner > .header-content` 안에 로고와 `nav .gnb`가 배치된다.

- 로고 이미지 기본 너비: 154px, 최대 높이 42px
- 헤더 패딩: 위아래 8px
- 헤더 콘텐츠 최소 높이: 62px
- GNB는 Flex로 가로 정렬하며 항목 간격은 `clamp(22px, 3.5vw, 58px)`
- GNB 버튼은 투명 배경, 차콜 텍스트, 18px / 600 / 1.5 행간
- GNB의 hover, focus-visible, `aria-expanded="true"` 상태에서 글자색은 브랜드 그린

서브 페이지에서는 로고, 메뉴 이름, 순서, 기본 타이포그래피를 공유한다. 현재 헤더는 `position: absolute`로 화면 상단에 겹치는 메인 페이지 구조이므로, 서브 페이지에서는 콘텐츠와 겹치는지 확인한 뒤 같은 외형을 유지하는 배치 방식을 선택한다.

### 7.2 Mega Menu

- `.mega-menu`는 전체 너비를 사용한다.
- `.mega-menu-inner`는 PC 6열 Grid로 구성한다.
- 링크는 16px / 400 / 1.5 행간이다.
- 열림 상태에는 상단에 브랜드 그린 1px 구분선을 표시한다.
- 배경은 헤더와 동일한 반투명 화이트다.
- 모바일은 3열, 380px 이하는 2열로 바뀐다.

### 7.3 Tabs

관련 클래스: `.menu-tabs`, `.menu-tab`, `.news-tabs`, `.news-tab`

- 버튼형 텍스트 탭이며 배경은 투명하다.
- 기본 글자색은 `--color-text-primary`, 활성 및 hover 글자색은 `--color-brand-pink`다.

- 아직 실제 페이지가 없는 메뉴는 존재하지 않는 URL을 임의로 연결하지 말고, 페이지 제작 시 확정한다.

## 8. Interaction

### GNB / 메가 메뉴

현재 인라인 JavaScript에서 확인되는 동작:

- 마우스 hover 지원 PC에서는 GNB에 마우스를 올리면 메가 메뉴를 연다.
- PC에서 헤더 영역을 벗어나면 메가 메뉴를 닫는다.
- 터치 환경에서는 GNB 버튼 탭으로 메가 메뉴를 열고 닫는다.
- 헤더 바깥 클릭 또는 Escape 키 입력으로 닫는다.
- 메가 메뉴의 링크를 클릭하면 메뉴를 닫는다.
- 열림 상태는 `aria-expanded` 속성으로 표시한다.

### 탭

- 클릭한 탭에 `is-active` 클래스를 적용한다.
- 메뉴 탭은 `data-menu-filter` 값과 카드의 `data-category`를 비교해 카드를 필터링한다.
- 뉴스 탭은 `data-news-filter` 값과 카드의 `data-news-type`을 비교한다.
- 필터에서 제외된 카드는 `hidden` 속성으로 숨긴다.

### 캐러셀

- 메뉴와 인스타그램 캐러셀은 이전·다음 버튼으로 이동한다.
- JavaScript는 첫 카드 너비와 트랙 gap을 계산해 `scrollBy()`로 이동한다.
- 이동 방식은 `behavior: "smooth"`다.
- 트랙은 가로 스크롤을 사용하며 스크롤바는 숨겨져 있다.

### Hover / Focus / Active / Transition

| 상태 | 현재 구현 |
|---|---|
| GNB hover | 글자색 그린 |
| GNB focus-visible | 글자색 그린 + 그린 2px 외곽선 |
| GNB 열림 | `aria-expanded="true"`일 때 글자색 그린 |
| 메가 메뉴 링크 hover | 글자색 그린 |
| 메뉴·뉴스 탭 hover | 글자색 핑크 |
| 메뉴·뉴스 탭 active | `.is-active`일 때 글자색 핑크 |
| 메뉴 카드 hover | 이미지 위로 4px 이동 + 핑크 그림자 |
| 뉴스 카드 hover | 이미지 위로 3px 이동 |
| CTA hover | 배경 레드 + 위로 2px 이동 |
| 캐러셀 화살표 hover | 글자색 핑크 |
| 링크·버튼 focus-visible | 그린 2px 외곽선, 4px offset |

### Transition 시간

- GNB 글자색: 160ms
- 헤더 배경색: 180ms
- CTA 배경·위치: 180ms
- 메뉴 카드 이미지: 220ms
- 뉴스 카드 이미지: 200ms

### 모션 감소 설정

`prefers-reduced-motion: reduce`에서 페이지의 부드러운 스크롤을 끄고 일부 transition을 제거한다. 서브 페이지에 새 모션을 추가하더라도 사용자의 모션 감소 설정을 존중한다.

## 9. Responsive Rules

현재 `main.css`의 실제 미디어 쿼리 기준은 1100px, 700px, 380px이다.

### 1100px 이하

- 헤더 좌우 너비를 `calc(100% - 48px)`로 조정한다.
- 로고 너비를 130px로 줄인다.
- GNB 글자 크기를 16px로 줄이고 항목 간격을 좁힌다.
- 메가 메뉴 내부 좌우 너비를 48px 여백으로 맞춘다.
- 섹션 패딩은 `80px 24px 56px`로 변경한다.
- 뉴스 그리드는 4열에서 2열로 변경한다.
- 브랜드 영역의 간격을 44px로 줄인다.
- 푸터 상단·하단은 줄바꿈을 허용한다.

### 700px 이하

- 헤더 좌우 여백은 16px, 콘텐츠 최소 높이는 60px다.
- 로고는 90px 너비, 최대 높이 34px다.
- GNB는 가로 스크롤이 가능하며 스크롤바는 숨긴다.
- 메가 메뉴는 3열 Grid로 변경한다.
- 히어로는 `100dvh`를 유지한다.
- 섹션 패딩은 `62px 16px 48px`다.
- 메뉴 탭 간격을 줄이고 메뉴 카드는 가로 스크롤 구조로 전환한다.
- 브랜드 영역은 1열로 변경한다.
- 뉴스 그리드는 1열로 변경한다.
- 인스타그램 카드도 가로 스크롤 형태로 보여준다.
- 푸터는 세로 배치로 변경한다.

### 380px 이하

- 헤더 좌우 여백은 10px, 로고 너비는 72px다.
- GNB 간격은 10px, 글자 크기는 14px다.
- 메가 메뉴는 2열 Grid로 변경한다.
- 메뉴·뉴스 탭 글자 크기는 13px이다.
- 뉴스 제목 영역은 세로 정렬로 변경한다.

### 서브 페이지 반응형 적용 규칙

- 먼저 위 세 브레이크포인트를 기준으로 제작한다.
- 메인 페이지와 동일하게 콘텐츠 폭, 좌우 여백, 글자 크기를 단계적으로 조정한다.
- 카드가 많거나 폭이 좁은 콘텐츠는 열 수를 줄인다.
- 모바일에서 가로 스크롤을 사용하는 경우, 좌우 이동이 가능한 UI임을 사용자가 알아볼 수 있게 한다.
- 위 기준으로 해결되지 않는 페이지 고유의 레이아웃 문제가 있을 때만 추가 미디어 쿼리를 작성한다.

## 10. Do & Don't

### Do

- [ ] 기존 CSS 변수(`--color-brand-pink`, `--color-brand-green`, `--color-brand-red` 등)를 재사용한다.
- [ ] 기본 글꼴은 Pretendard Variable을 사용한다.
- [ ] 콘텐츠 컨테이너는 `--content-max-width`를 기준으로 맞춘다.
- [ ] 공통 헤더와 푸터의 구조·색상·타이포그래피를 일관되게 유지한다.
- [ ] CTA는 기존 `.pill-link` 패턴을 우선 재사용한다.
- [ ] 카드 이미지 비율은 같은 목록 안에서 통일한다.
- [ ] 버튼은 동작에, 링크는 페이지 이동에 사용한다.
- [ ] hover뿐 아니라 키보드 `:focus-visible` 상태도 제공한다.
- [ ] 모바일에서 1100px, 700px, 380px 기준을 확인한다.
- [ ] 이미지에 적절한 대체 텍스트를 제공한다.
- [ ] 기존 메인 페이지의 디자인과 동작을 변경하지 않고, 서브 페이지 전용 스타일을 추가한다.

### Don't

- [ ] 근거 없이 새로운 브랜드 컬러나 임의의 디자인 토큰을 만들지 않는다.
- [ ] 페이지마다 서로 다른 폰트나 제목 위계를 사용하지 않는다.
- [ ] 같은 역할의 CTA를 페이지마다 다른 모양으로 만들지 않는다.
- [ ] 카드 목록 안에서 이미지 비율과 간격을 제각각 적용하지 않는다.
- [ ] hover 색상만으로 선택 상태나 기능 상태를 전달하지 않는다.
- [ ] 모바일에서 PC 레이아웃을 그대로 축소해 글자와 버튼이 지나치게 작아지게 하지 않는다.
- [ ] 실제로 존재하지 않는 페이지 주소나 외부 브랜드 사이트 주소를 임의로 연결하지 않는다.
- [ ] 기존 메인 페이지의 CSS·HTML·JavaScript를 서브 페이지 제작 과정에서 불필요하게 수정하지 않는다.
- [ ] 코드에서 확인되지 않은 수치를 기존 디자인 규칙인 것처럼 문서에 추가하지 않는다.

## 분석 시 확인된 구현 메모

다음 내용은 디자인 변경 요청이 아니라, 저장소 코드에서 확인된 사항을 기록한 것이다.

1. `index.html`의 JavaScript는 별도 JS 파일이 아니라 HTML 하단의 인라인 `<script>` 안에 작성되어 있다.
2. `index.html`에는 `CSS/neo-brutalism.css`를 불러오는 링크가 있으나, 이번 분석에서 해당 경로의 파일 내용을 확인하지 못했다. 실제 저장소의 파일명과 경로를 별도로 확인해야 한다.
3. `index.html`에서 `main.css` 링크 뒤에 문자 그대로의 `\n`이 포함된 형태가 확인되었다. 브라우저에서 스타일시트 경로가 정상적으로 처리되는지 확인할 필요가 있다.
4. `--color-border-light`는 변수로 선언되어 있지만 현재 확인한 `main.css`에서는 사용처가 확인되지 않았다.
5. 메가 메뉴를 열 때 현재 JavaScript는 모든 GNB 버튼의 `aria-expanded`를 `true`로 설정한다. 이는 현재 동작 구현에 대한 관찰이며, 이 문서 작성 과정에서 코드를 변경하지 않았다.

> 이 문서는 메인 페이지를 변경하기 위한 문서가 아니다. 메인 페이지에서 확인된 디자인 규칙을 서브 페이지에 일관되게 적용하기 위한 기준으로 사용한다. 실제 서브 페이지 제작 과정에서 공통으로 반복되는 UI가 추가되면 근거가 되는 구현을 확인한 뒤 문서를 갱신한다.
